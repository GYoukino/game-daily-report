# 游戏活动监测（GameActivityMonitor）

自动监控 **9 款游戏的官方渠道** + **4 个官方展会/票务平台**，发现新内容时推送到飞书（或微信），  
每天生成一份网页版（HTML）**前瞻资讯日报**——可发布成公开网页，在飞书里点开链接直接阅读完整内容。

监控的游戏：

| 厂商   | 游戏                       |
| ---- | ------------------------ |
| 米哈游  | 原神、崩坏：星穹铁道、绝区零、崩坏3、未定事件簿 |
| 鹰角网络 | 明日方舟、明日方舟：终末地            |
| 库洛   | 鸣潮                       |
| 深蓝互动 | 重返未来：1999                |

线下展会与票务平台：

| 平台 / 展会 | 说明 |
| --- | --- |
| BilibiliWorld 2026 | 哔哩哔哩会员购官方票务接口（项目 ID 可在 config.toml 增加） |
| The Game Awards | 官网新闻列表（含 TGA 举办日期、门票开售等前瞻信息） |
| gamescom | 官网新闻列表（Opening Night Live 等官方节目） |
| Summer Game Fest | 官网活动列表（当期结束后自动留空，下届自动恢复） |

工作方式：每 30 分钟检查一遍各官方来源 → 发现**没见过的内容**就推送 → 顺手更新当日 HTML 日报。  
第一次运行只"建档"（把现有内容记为已看过，不推送），之后只推送真正的新内容。

> **数据源原则（2026-10-22 起）**：只采**官方机构与官方渠道**（游戏官网接口 + 官方票务/展会平台），
> 不接第三方资讯站与 Wiki。第三方来源标注与"兑换码汇总页"采集器已一并移除。

## 零、这套东西现在有哪几种跑法

代码完全零第三方依赖（只用 Python 标准库 + git 命令行），所以挪到哪台机器上都能跑。目前三种跑法并存，互不冲突：

| 跑法 | 谁负责定时 | 适合场景 | 现状 |
| --- | --- | --- | --- |
| **① 本机计划任务** | Windows 任务计划程序（每天 10:00） | 只在自己电脑上跑 | 已在用，`run_community.bat` |
| **② GitHub Actions** | GitHub 云端（每天北京时间 10:00） | **推荐**：电脑和 NAS 都不用开 | 已配好，见 `.github/workflows/daily.yml` |
| **③ NAS 归档容器** | 容器里的 cron（每周一 04:00） | 把历史日报留一份在自己硬盘 | 见 `nas-archive/` |

三种跑法产出完全一样：**网页版日报页 + 飞书推送卡片**。

### 首次使用 Actions 需要你在 GitHub 网页上做两件事

1. **填两个密钥**（脚本不要写死密钥，这是故意的）：
   Settings → Secrets and variables → Actions → **New repository secret**

   | Name | Value |
   | --- | --- |
   | `FEISHU_WEBHOOK` | 飞书机器人的 Webhook 地址（从本机 `secrets.local.toml` 里复制） |
   | `FEISHU_SECRET` | 同上文件里的签名密钥 |

2. **给 Actions 写权限**，否则它没法把日报提交回仓库：
   Settings → Actions → General → Workflow permissions → 选 **Read and write permissions** → Save

配好后想立刻验证：Actions 页面左侧选 `每日游戏前瞻日报` → 右上角 **Run workflow**。

> 带图的傻瓜版教程见 **`docs/GitHub配置教程_小白版.html`**（双击就能在浏览器里看），
> 里面也写清了「这个仓库现在对外公开什么、不公开什么、想改成私有要付出什么代价」。

> 小提醒：GitHub 对长期无动静的仓库会停用定时触发器，但我们每天都在提交，不存在这个问题。
> 另外 Actions 的执行时间会有几分钟排队延迟，属于正常现象。

| `run_community.bat`      | 双击 = 本机手动跑一轮                           |
| `register_community_task.bat` / `unregister_community_task.bat` | 注册 / 卸载 Windows 计划任务（每天 10:00，可选） |

## 二、本机手动跑 / 本机定时跑（可选，云端 Actions 之外的补充）

> 云端 Actions（第零节）已经每天自动跑一遍，**本机这一节不是必需的**。
> 需要临时补跑、或者想在自己电脑上留一份最新报告时用。

**手动跑一轮**：双击 `run_community.bat`。
黑窗口会显示每一步进度（抓了几个源、生成多少条、有没有推送成功），跑完自动关闭或按键退出。

**让本机也每天定时跑**（双保险，关了电脑就不跑）：
右键 `register_community_task.bat` → **以管理员身份运行** → 看到"注册成功"即可。
想取消：右键 `unregister_community_task.bat` → 以管理员身份运行。

> 本机和云端同一天各跑一次不会冲突：当天报告会被覆盖重写成同一份，网页和飞书看到的仍是当天最新结果（飞书可能收到两条）。

## 三、配置飞书推送（可选但推荐）

不配置也能用（只生成 HTML 报告）；配置后新公告会推到飞书群。  
飞书群机器人**完全免费、没有每日条数上限**，是当前推荐渠道。

1. 电脑端打开飞书，找任意一个群（可以自己建一个只有自己的群）→ 右上角**群设置**。
2. **群机器人 → 添加机器人 → 自定义机器人**，起个名字（如"游戏监测"）。
3. 安全设置选 **"签名校验"**（推荐），然后复制两样东西：
   - **Webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx-xxxx-...`）
   - **签名密钥**（只显示一次，务必当场保存；丢了只能删掉机器人重建）
4. 用记事本打开本目录下的 `config.toml`，找到这两段并修改：
   ```toml
   [notify.feishu]
   enabled = true
   webhook = "你的Webhook地址粘在这里"
   secret = "你的签名密钥粘在这里"
   ```
5. 保存，然后**双击 `run_community.bat` 跑一轮**，飞书群里收到日报卡片即配置完成。
   （命令行等价写法：`python community_report.py`）

> 备用渠道：`[notify.serverchan]`（Server酱，免费版 5 条/天）仍保留，  
> 飞书推送失败时会自动尝试 Server酱（需两边都配置）。  
> 多渠道的优先级和新增方法见 `notifier.py` 末尾的 `build_notifiers()`。

> 注意：第一次运行只建立基线、不推送。想测试推送效果，可以临时把  
> `notify_on_first_run = true`，跑一轮收到全部公告后，再改回 `false`。

## 三之二、配置网页日报：GitHub Pages（可选，强烈推荐）

> 📖 **零基础用户**：`docs/GitHub配置教程_小白版.html` 双击用浏览器打开，
> 是一步一图（操作/注意事项/预期结果）的详细图文教程，跟着点即可，约 15 分钟。
> 下面是与代码/配置对应的速查版说明。

配置后，每天的 HTML 日报会**自动发布成一个公开网页**，飞书推送卡片底部带「📄 查看今日完整日报」链接——点开即可在飞书内置浏览器里浏览排版好的完整日报（公告链接全部可点），历史日报自动沉淀在门户页里，随时回看。

1. 登录 <https://github.com/> （没有账号就注册一个，约 2 分钟；用户名会出现在网址里）。
2. 点右上角 **+ → New repository**，建一个 **Public** 仓库（建议名 `game-daily-report`），
   **不要勾选** "Add a README file" 等初始化选项。
3. 仓库页面 **Settings → Pages → Source** 选 `Deploy from a branch`，Branch 选 `main`、文件夹选 `/(root)`，Save。
   记下给出的网址（形如 `https://用户名.github.io/game-daily-report/`）。
   > 空仓库此时在 Branch 下拉里还选不到 `main`（显示 "No results found"）——**正常**：先不保存，完成第 5 步首次发布后再回来选 `main` 保存。
4. 用记事本打开 `config.toml`，找到 `[publish.github]` 段并修改：
   ```toml
   [publish.github]
   enabled = true
   username = "你的GitHub用户名"
   repo = "game-daily-report"
   ```
5. 保存，双击 `run_community.bat`：**首次会弹出 GitHub 登录窗口**（或用系统已保存的凭证），
   登录一次后系统记住，以后自动推送不再打扰。看到输出「成功：网页链接 https://...」即发布完成。
   > 云端 Actions 不需要这一步——它用仓库内置的 `GITHUB_TOKEN` 提交。
6. 等 1-2 分钟（GitHub 部署延迟），打开链接确认能正常阅读；把门户页链接发到飞书聊天里点开验证。

**行为说明**：
- 只在「当天有新公告」时才发布（内容没变不重复推），平均一天几次
- 门户页 `https://用户名.github.io/仓库名/` = 今日入口 + 历史日报列表；日报页 `.../daily/日期.html`
- 发布失败只记日志，**不影响**飞书推送和本地 HTML 报告
- 完全免费（公开仓库的 GitHub Pages 不收费）；内容均为各游戏官网公开公告

## 四、日报在哪看

日报已升级为**《游戏前瞻资讯汇总》**——不再是全量公告流水账，而是按资讯类型整理的前瞻情报：

- 📅 **关键节点时间线**（未来约 100 天的直播 / 活动 / 截止日）
- 📺 **前瞻直播 / 特别节目**（时间与观看入口）
- 🗺️ **版本前瞻内容汇总**（新角色 / 新剧情 / 新玩法）
- 🎁 **限时兑换码及有效期**（按截止时间排序，自动标注已过期）
- 🤝 **线下联动活动**（时间 / 地点 / 参与方式）
- 🛍️ **官方周边上新信息**
- ⚡ **快闪店活动安排**
- 🎪 **漫展 / 展会活动详情**
- 📚 **信息来源与时效性说明**（官宣 / 待官宣 / 爆料 / 第三方 / 已过期 五级标注）

已**排除**：游戏内公告、卡池频次、系统维护 / 停机 / 闪断、处罚公示、问题修复与补偿、
未成年人限时等非前瞻内容。日报呈现的是"当前有效的前瞻资讯全景"——未来的直播和活动
会持续展示，过期自动标灰。

三个查看入口：

1. **本地文件**：`reports\游戏前瞻日报_2026-10-22.html`，双击用浏览器打开。
2. **网页版**（配置 GitHub Pages 后）：飞书推送卡片底部带链接，点开即在飞书内阅读；
   门户页可回看所有历史日报。详见「三之二」。
3. **飞书群消息**：监测到新的前瞻资讯时按游戏分组推送（非前瞻内容不推送，不打扰）。

> **格式规范（2026-10-22 起强制执行）**：日报排版以《游戏前瞻资讯汇总_2026-10-21.html》
> 为唯一标准——同一套 CSS 设计系统（蓝紫主色 `#4a6cf7`、渐变头图、`section`+`h2` 分区、
> 浅蓝表头表格、彩色标签 pill、时间线组件、统一页脚）。`forward_report.py` 中的 CSS
> 与样式类不得随意改动（有自动化测试逐行比对目标文件）。

### 数据从哪来

| 来源类型 | 覆盖板块 |
|---|---|
| 9 个游戏官网源（config.toml `[[games]]`，`source` 为 `mihoyo_content` / `arknights_web` / `endfield_web` / `kuro_json` / `bluepoch_api`） | 前瞻直播、版本前瞻、联动、周边官宣 |
| `bili_mall`（哔哩哔哩会员购官方票务接口） | 漫展展会：BW 等线下活动的时间 / 地点 / 票务 |

**关于兑换码**：只走官方渠道后，兑换码板块仅在官方确实发布时出现（如前瞻直播兑换码）；
官网不发码的日期该板块显示空态——这是"只采官方渠道"的必然结果，不做第三方补录。

ChinaJoy 官网（SPA 空壳无可抓接口）、CP 漫展（官方票务 CPP 需登录）、
天猫/淘宝品牌旗舰店（登录墙）、B站官号动态（接口风控）。

## 五、日常维护

- **报告堆积**：`reports/` 里每天一个 HTML，可定期把旧文件移到别处或删除（只删报告，不影响运行）。
- **改配置**：编辑 `config.toml`，保存后下一轮自动生效（云端 Actions 会在第二天 10:00 生效；
  本机想立刻看效果就双击 `run_community.bat`）。
- **想临时停掉某款游戏**：把 config.toml 里对应 `[[games]]` 块的 `enabled = true` 改成 `false`。
- **本程序不写本地数据库**：每次运行都是「当场抓取 → 当场出报告」，没有需要维护的状态文件，
  换电脑只需把代码和 `secrets.local.toml` 拷过去即可。
- **跑挂了怎么查**：云端看 Actions 运行日志；本机双击 `run_community.bat` 直接看黑窗口输出。
- 想验证链接有没有失效（官网改版常见），跑 `python check_links.py`。

## 六、怎么添加新游戏

**情况 A：新游戏属于已支持的 5 种官网结构之一**（推荐，零代码）

1. 打开 `config.toml`，复制一段 `[[games]]` 块，粘贴到文件末尾，改参数：
   ```toml
   [[games]]
   name = "游戏显示名"
   enabled = true
   source = "mihoyo_content"        # 采集器类型，见下方说明
   url = "公告接口或网页地址"
   params = { iChanId = 123, iPageSize = 20, iPage = 1, sLangKey = "zh-cn" }
   detail_url = "公告详情页链接，{id} 会被替换成公告ID"
   ```
2. 保存后跑一轮验证（双击 `run_community.bat`），并跑 `python check_links.py` 确认新链接可达。

采集器类型对照：

| source           | 适用官网结构                 |
| ---------------- | ---------------------- |
| `mihoyo_content` | 米哈游系游戏通用接口（content_v2） |
| `arknights_web`  | 明日方舟官网（网页解析）           |
| `endfield_web`   | 明日方舟：终末地官网（网页解析）       |
| `kuro_json`      | 库洛系静态 JSON 公告（鸣潮）      |
| `bluepoch_api`   | 重返未来：1999 官网接口         |
| `bili_mall`      | 哔哩哔哩会员购票务项目（开放接口，按项目 ID） |
| `expo_next`      | 海外展会官网新闻/活动列表（TGA / gamescom / SGF） |

**情况 B：新游戏官网结构完全不同**

需要在 `fetchers.py` 里写一个新的采集器类（实现 `fetch(name, cfg)` 方法，返回公告列表），  
并在文件底部的 `FETCHERS` 注册表里登记，然后在 config.toml 里引用。这一步需要懂一点 Python，  
可以请会编程的朋友帮忙，或联系本项目维护者。

## 七、常见问题

**Q：提示"找不到 config.toml"？**  
程序必须在本目录内运行。计划任务模式已自动处理；手动运行时请先双击/进入本目录再执行。

**Q：有公告但收不到推送？**  
依次检查：① `secrets.local.toml` 里 `[notify.feishu]` 的 `enabled = true` 且 `webhook` 已填写（本机双击 `run_community.bat` 看黑窗口的具体报错；云端则检查仓库 Secrets 里 `FEISHU_WEBHOOK`/`FEISHU_SECRET` 的两个**名称**是否全大写、值是否多了空格）；② 只推送前瞻类新条目，非前瞻内容不打扰（这是设计如此，不是故障）；③ 飞书机器人是否被移出群聊（Webhook 会失效）；④ 若用 Server酱 备用渠道，检查当天 5 条免费额度是否用完。

**Q：1999（重返未来）为什么只有英文公告？**  
其官网接口当前只开放"全球服"公告（英文）。国服特有公告暂无法从该接口获取。

**Q：未定事件簿 / 鸣潮的公告链接点了打不开？**  
这两款官网的详情页地址规则未公开，报告里的链接暂时用官网首页/新闻页兜底，标题和时间是准确的。

**Q：电脑休眠期间会漏推吗？**  
不会漏抓。休眠唤醒后的下一轮会把期间发布的新公告一次性补齐并推送（按游戏分组，每款一条）。

**Q：网页日报链接打不开 / 发布失败？**  
先看 `docs/GitHub配置教程_小白版.html` 文末的排错表。最常见四个原因：刚推送完还没部署好（等 1-2 分钟刷新）；仓库是私有的（私有仓库 Pages 需付费，改成 Public）；Pages 设置里分支没选 `main`；**Actions 的 Workflow permissions 没设成 Read and write**（这步漏了会导致日报生成了却推不回仓库）。

## 八、技术说明（给想改代码的人）

- 纯 Python 3 标准库实现（urllib/json/re/tomllib），**无需安装任何第三方包**。
- 模块划分：`fetchers.py`（数据采集：9 官网源 + 会员购票务接口 + 海外展会官网）→ `storage.py`（去重与存储）→ `classifier.py`（七类前瞻资讯分类 + 非前瞻排除 + 时效性提取）→ `forward_report.py`（前瞻日报渲染，版式对标《游戏前瞻资讯汇总》）→ `notifier.py`（多渠道推送：飞书/Server酱）→ `publisher.py`（发布到 GitHub Pages）→ `engine.py`（总流程调度）。
- 数据源（均已实测可用）：
  - 米哈游 5 款：`content_v2_user/app/{appKey}/getContentList` 接口
  - 明日方舟 / 终末地：官网新闻页 Next.js flight 数据解析
  - 鸣潮：官网静态 JSON（ArticleMenu.json）
  - 1999：官网 `information/query` POST 接口
  - 哔哩哔哩会员购：`show.bilibili.com/api/ticket/project/getV2?id={项目ID}`（开放接口，无需登录）
  - TGA / gamescom：官网 Next.js flight 数据解析（条目自带发布日期）
  - Summer Game Fest：官网静态页按 `cms-event-item` 块解析
- 前瞻分类口径：七类（直播/版本前瞻/兑换码/联动/周边/快闪/漫展）白名单命中即归类；
  排除词表（维护/停机/处罚/修复/补偿/卡池/频次/未成年人限时等）优先于分类。
  例外：标题含「版本更新公告 / 版本更新说明 / 新版本更新」且不含硬排除词（维护/停服/补偿/卡池等）
  的条目按版本前瞻收录（新版本上线节点是玩家最关心的前瞻信息）；另「活动预告 / 即将开启 /
  限时活动 / 主线更新」也归入版本前瞻。
- **时间线口径**：「今天 00:00 起 N 天内」（N = `settings.timeline_horizon_days`，默认 100），
  已过期 / 已结束 / 档期待确认的条目不占时间线，只留在各自分类板块里。
  日期提取支持 `2026年10月30日`、`2026/10/30`、`2026-10-30`、`10月30日`、`October 29, 2026`
  五种写法，月日缺省年份时以条目发布时间为基准推断。
- **历史回溯**：`--backfill` 让支持翻页的源（mihoyo_content / bluepoch_api）按
  `params.backfill_pages` 连翻多页；条目正文入库保留 2000 字（展示只取 110 字），
  以便从正文深处提取活动起止日期。
- 实测状态：
  - 飞书 Webhook 推送：已实测通过（含签名校验）
  - GitHub Pages 发布链路：本地裸仓库全流程实测（首次自动 init/推送、重复发布跳过、远端领先自动合并再推、门户页生成）+ 网络波动自动重试 3 次；真实远端已配置并推送成功（GYoukino/game-daily-report）
  - 前瞻分类与日报渲染：45 项分类单测 + 32 项结构/CSS 比对测试全部通过（CSS 与目标格式逐行一致）
  - 2026-10-22 重构后全链路实测：`--once` 抓到 374 条（含 gamescom 15 / TGA 3 / BW 1），
    前瞻日报 16 条（版本前瞻 7 + 漫展展会 9）→ 发布线上 200 → 飞书测试卡片带链接成功
  - 计划任务注册脚本已提供，注册流程需在本机以管理员身份实际执行确认
- 常用命令：`python community_report.py`（跑完整一轮：抓取 + 生成 + 发布 + 推送）、
  `python check_links.py`（配置路由校验 + 日报外链 404 体检）。
