🌐 网页日报（GitHub Pages）· 配置指南（小白版）

按下面 7 步操作，每天的日报就会自动发布成一个精美网页，
飞书推送消息底部带链接，点开即可在飞书里阅读完整日报。
⏱ 预计耗时：约 15 分钟　｜　难度：⭐⭐（照着点即可）

📋 先看看这张任务清单

  • 第 1 步：注册并登录 GitHub（已有账号可跳过）
  • 第 2 步：新建一个公开仓库
  • 第 3 步：给仓库开启 Pages 功能
  • 第 4 步：把用户名和仓库名填进 config.toml
  • 第 5 步：双击 run_test_publish.bat 做首次发布
  • 第 6 步：打开链接，确认网页能正常看
  • 第 7 步：日常使用说明（看看就好，无需操作）
💡 开始前说明：你的飞书推送（群里收到的公告卡片）已经在正常工作。这份指南是给它加一项能力——完整日报以网页形式呈现。之前设想的「飞书云文档」路线对个人账号已被飞书官方限制（错误码 21001），所以改走 GitHub Pages：同样是在飞书里点开链接看完整内容，而且排版更好、完全免费。做不完随时可以停下来，不影响现有推送。
1

注册并登录 GitHub

约 2 分钟

🛠 具体操作

  1. 打开浏览器，访问 github.com。
  2. 点右上角 Sign up（注册）。
  3. 按提示输入邮箱、设置密码、起一个用户名，完成验证。

⚠️ 注意事项

  • 用户名会出现在最终的网址里（形如 https://你的用户名.github.io/仓库名/），起个简单易认的。
  • 注册后如果邮箱里收到验证邮件，点一下链接完成验证。
  • 已经有 GitHub 账号：直接登录，跳到第 2 步。

✅ 预期结果

登录后看到 GitHub 首页（左上角有猫头鹰图标，右侧有你的头像）。
小知识：GitHub 是全球最大的代码托管网站，我们借用它的「Pages」功能免费放网页，就像免费网盘一样。
2

新建一个公开仓库

约 2 分钟

🛠 具体操作

  1. 登录后，点页面左上角头像旁边的 + 号，选 New repository（新建仓库）。
  2. Repository name（仓库名）填：game-daily-report（也可以起别的名，但下面第 4 步要填一致的名字）。
  3. 类型选 Public（公开）——公开仓库的 Pages 功能才免费。
  4. 下面所有的初始化选项都不要勾选（特别是 "Add a README file"），保持空仓库。
  5. 点绿色按钮 Create repository。

⚠️ 注意事项

  • 仓库名只能用英文、数字和连字符，不要用中文和空格。
  • 千万别勾 "Add a README file"：空仓库才能让程序第一次推送顺畅成功；勾了会产生冲突（程序虽能自动处理，但没必要给自己找事）。
  • 仓库放的都是游戏官网的公开公告，没有隐私内容，公开没有关系；如果介意，见文末 FAQ。

✅ 预期结果

进入一个空仓库页面，中间显示 "Quick setup — …or create a new repository on the command line" 之类的提示，没有任何文件。把浏览器地址栏里 github.com/ 后面那段记住——那就是「用户名/仓库名」，第 4 步要用。
3

给仓库开启 Pages 功能

约 2 分钟

🛠 具体操作

  1. 在仓库页面顶部菜单找到 Settings（齿轮图标），点进去。
  2. 左侧菜单找到 Pages，点它。
  3. 找到 Source（来源）这一项，选择 Deploy from a branch。
  4. 下面出现 Branch（分支）选择：选 main，右边文件夹选 / (root)。
  5. 点 Save。

⚠️ 注意事项

  • 如果分支下拉框里没有 main、提示 "No results found"、保存按钮点不了：这是正常现象——仓库现在是空的（按第 2 步要求没建 README），还没有任何分支可选。先跳过本步不保存，直接去完成第 5 步（双击 run_test_publish.bat 首次发布）；推送成功后仓库里就有了 main 分支，再回到本页面选分支保存即可。
  • 分支一定要选 main（和程序默认一致）；如果你的仓库默认分支不叫 main，第 4 步配置里也要相应修改 branch。
  • 保存后页面顶部会显示一行提示：Your site is ready to be published at https://用户名.github.io/game-daily-report/——这就是以后的日报网址，先记下来。
  • 现在打开这个网址还是 404，正常，因为仓库里还没有文件，第 5 步发布后才有内容。

✅ 预期结果

Pages 设置页显示 "GitHub Pages" 已启用，并给出了你的专属网址（形如 https://用户名.github.io/game-daily-report/）。
4

把信息填进 config.toml

约 2 分钟

🛠 具体操作

  1. 打开项目文件夹 game-activity-monitor，找到 config.toml，用记事本打开。
  2. 找到文件里 [publish.github] 这一段（在说明注释的下方）。
  3. 把 enabled = false 改成 enabled = true。
  4. 把 username = "" 的引号里填上你的 GitHub 用户名。
  5. 把 repo = "" 的引号里填上仓库名（第 2 步起的，如 game-daily-report）。
  6. 保存（Ctrl+S），关闭记事本。

⚠️ 注意事项

  • 引号要保留：正确写法是 username = "zhangsan"，不要把引号删掉。
  • 用户名、仓库名必须和第 2 步建的完全一致（区分大小写）。
  • 只改这三项，其他保持原样。

✅ 预期结果

配置段看起来像这样： 
[publish.github]
enabled = true
username = "zhangsan"
repo = "game-daily-report"
branch = "main"
5

首次发布测试

约 3 分钟

🛠 具体操作

  1. 回到项目文件夹，双击 run_test_publish.bat。
  2. 第一次会弹出一个 GitHub 登录窗口（浏览器或独立小窗）——这是程序在向你的仓库推送文件，需要你授权一次。
  3. 在窗口里登录 GitHub 并授权（如果浏览器已登录 GitHub，点几下即可）。
  4. 授权后窗口自动关闭，黑框里继续滚动文字，直到出现「成功」和一条链接。

⚠️ 注意事项

  • GitHub 登录只需要第一次，凭证会被系统记住，以后每天自动推送不再打扰你。
  • 如果窗口迟迟不弹 / 一直卡住：按 Ctrl+C 或直接关掉窗口，先确认能正常打开 github.com，再重试。
  • 黑框里的英文看不懂没关系，只看最后几行有没有「成功」。

✅ 预期结果

黑框最后几行长这样（链接里的用户名/仓库名是你自己的）： 
[发布测试] 今日报告已生成（N 条） -> ...reports\游戏动态日报_2026-10-22.html
[发布测试] 成功：网页链接 https://zhangsan.github.io/game-daily-report/daily/2026-10-22.html
[发布测试] GitHub Pages 部署通常需要 1-2 分钟，稍等再打开链接
看到「成功」二字，说明文件已经推到 GitHub 了。
6

打开链接，确认能正常看

约 2 分钟

🛠 具体操作

  1. 等 1-2 分钟（GitHub 需要一点时间把网页发布出来）。
  2. 复制第 5 步黑框里那条链接，粘贴到浏览器打开——应该能看到和本地报告一样精美的日报页面，标题、分类、公告链接都能点。
  3. 再打开第 3 步记下的门户页网址（不带 daily 的那条）——能看到「进入今日日报」大按钮和历史日报列表。
  4. 最后把门户页链接发到飞书任意聊天（比如"文件传输助手"），点开验证——能在飞书里直接看，就大功告成了。

⚠️ 注意事项

  • 刚推送完马上打开可能显示 404，等 1-2 分钟刷新即可，这是 GitHub 的正常部署延迟。
  • 如果超过 5 分钟还是 404，看文末 FAQ 第一条。

✅ 预期结果

浏览器和飞书里都能正常打开日报网页，公告标题点击可跳转到官网。从今往后，飞书推送的公告卡片底部都会带这条链接。

日常使用（无需操作，看看就好）

🛠 之后会发生什么

  • 监测程序每轮发现新公告 → 自动更新本地报告 → 自动推送到 GitHub → 网页自动更新。
  • 飞书群收到的公告卡片底部会带「📄 查看今日完整日报」链接，点开就是当天完整内容。

⚠️ 注意事项

  • 想换台电脑 / 重装系统后继续用：重新跑一次第 5 步登录一次即可，数据都在 GitHub 上。
  • 门户页链接建议收藏到飞书「收藏」或浏览器书签，每天点开就是最新日报。
  • 如果某天没有任何新公告，网页就不会更新（内容没变，没必要推），推送也会相应安静一天。

✅ 预期结果

无需任何操作。以后每天在飞书里点链接看日报即可。

❓ 常见问题（FAQ）

Q1：链接打开是 404 页面怎么办？
按顺序检查三点：① 是不是刚推送完？等 1-2 分钟再刷新；② 回 GitHub 仓库 Settings → Pages，确认 Source 选的是 "Deploy from a branch"、分支是 main、文件夹是 /(root)，并已 Save；③ 仓库是不是 Public（私有仓库的 Pages 需要付费的 GitHub Pro，把仓库改成 Public 即可：Settings 页最下方 General → Danger Zone → Change visibility）。
Q2：双击 run_test_publish.bat 没反应 / 提示找不到 Python？
bat 里已经内置了本机 Python 路径。如果换了 Python 安装位置，改用命令行方式：在项目文件夹空白处按住 Shift 点鼠标右键 → "在此处打开 PowerShell 窗口"，输入 python main.py --test-publish 回车。
Q3：推送时提示超时 / 连接被重置（connection reset）/ 网络错误？
这是国内访问 GitHub 时的瞬时波动，很常见，不代表配置有错。程序检测到网络类错误会自动重试 3 次（间隔几秒）；3 次仍失败时黑窗口会保留错误信息，确认浏览器能打开 github.com 后，重新双击一次 run_test_publish.bat 即可。如果反复失败，可能是所在网络拦截 git 流量，换手机热点试一次就能判断。
Q4：以后每天会往 GitHub 推很多文件吗，会不会很乱？
不会。程序只在「有新公告」时才推送一次，平均一天几次；每次只是一个日期文件的小改动，GitHub 会自动保存历史版本，你的仓库页面看起来始终只有 index.html 和 daily/ 文件夹两项，很干净。
Q5：我不想把日报公开，有办法保密吗？
两个选择：① 接受现状——内容都是各游戏官网已公开的公告，网址不告诉别人就没人知道，实际暴露风险极低；② 不开通这个功能，继续用现在的飞书卡片推送 + 本地 HTML 报告（在项目 reports 文件夹里，双击就能看，排版一样精美，只是不能在飞书里直接打开）。
Q6：手机上怎么看？
把链接发到飞书任意聊天，点开就在飞书内置浏览器里显示，不用装任何 App。也可以把门户页链接添加到飞书「收藏」，随时点开。
Q7：之前那份《飞书云文档配置指南》还能用吗？
不能用了。飞书在 2026 年 10 月收紧了个人账号的接口权限，自建应用调用一律被拦（错误码 21001），这是平台策略，怎么配置都绕不过。这份 GitHub Pages 指南就是替代方案，效果相同且更稳定。那份旧指南留个纪念即可，不用再操作。
Q8：GitHub 用户名 / 仓库名以后能改吗？
能，但改了网址就变了。用户名在 GitHub 设置里改（一年内改动次数有限）；仓库名在仓库 Settings 里改。改完记得同步修改 config.toml 里的 username / repo，并重跑一次第 5 步。
